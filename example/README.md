# 工具案例：SSH 连通性测试（Node.js + ssh2）

> 这是 **tools 小工具平台**的一个完整工具案例。照着本文档把它装进平台，
> 主页面就会多出一个「SSH 连通性测试」图标，点击即可在平台内直接使用。
>
> 界面参考了 `ccp/sshTest` 项目（表单 + 分阶段结果），但整体改用 **Node.js + 原生 HTML/CSS/JS** 实现，
> 完全跑在平台自带的 Node 运行时上，不需要 Tauri 原生能力。

---

## 1. 这个工具能做什么

输入 SSH 连接信息，分三个阶段测试连通性，并给出每个阶段的耗时与结论：

1. **TCP 连接** —— 目标 IP:端口是否可达；
2. **SSH 握手** —— 目标端口是否真的是 SSH 服务、加密协商是否成功（记录服务端主机密钥指纹）；
3. **登录认证**（可选）—— 密码 / 私钥 是否正确，能否真正登进去。

支持：主机 / 端口 / 用户名、密码认证、私钥认证（含私钥口令）、验证登录开关、超时设置、
密码显示/隐藏、从工具目录选择私钥文件、结果分步展示。

还带一个**历史记录**面板（后端持久化到工具目录 `history.json`）：
- 点「保存当前」把当前表单存为一条记录；
- 点记录条目**一键填充**全部数据（含密码/私钥/超时等）；
- 「更新」用当前表单覆盖指定记录，「删除」移除单条，「清空」清除全部。

## 4. 在平台里新建这个工具（核心步骤）

> 平台会自动扫描用户数据目录下的 `toolbox/`（Windows：`%APPDATA%\com.tools.platform\toolbox`），
> 任何含 `manifest.json` 的子目录都会出现在启动器里。因此最简单的做法就是「复制目录」。

### 第 1 步：把案例放进工具箱

1. 打开用户数据目录：按 `Win + R`，输入 `%APPDATA%\com.tools.platform\toolbox`，回车。
   （也可以用文件管理器直接输入该路径。）
2. 把本目录下的 `ssh-connectivity-test/` 整个文件夹复制进去，最终结构：
   ```
   %APPDATA%\com.tools.platform\toolbox\ssh-connectivity-test\
   ├── manifest.json
   ├── index.html
   ├── styles.css
   ├── front.js
   ├── app.js
   └── package.json
   ```
3. 回到平台主页面，点右上角「刷新」，即可看到「SSH 连通性测试」图标。

### 第 2 步：安装 SSH 库（ssh2）⭐ 必做

本工具后端依赖 `ssh2`（纯 JS 的 SSH 客户端库，无需编译原生模块），**不装会启动失败**。用平台自带的依赖管理安装：

1. 主页面 →「依赖管理」。
2. 顶部下拉框选择工具 **SSH 连通性测试**。
3. 在输入框填 `ssh2`（本案例 `package.json` 已声明 `^1.16.0`，也可以直接写 `ssh2` 装最新）。
4. 点「安装」，等待进度完成。

安装后，工具自身的 `node_modules/` 里就有 `ssh2` 了，工具之间互不影响。

> 也可在命令行进入该工具目录手动执行 `npm install`（本机有 Node 时）。

### 第 3 步：运行

回到主页面，点击「SSH 连通性测试」图标 → 填写连接信息 → 「开始测试」。

### 方式 B：用平台内置编辑器（备选）

如果你不想复制文件夹，也可以：

1. 主页面 →「新建工具」→ 填名称（如 `SSH 连通性测试`）→ 选 **blank** 模板 → 创建。
2. 进入编辑器，把本案例的 `manifest.json`（id 改成 `ssh-connectivity-test`）、`index.html`、`app.js`、
   `styles.css`、`front.js` 内容逐个粘贴到对应文件（编辑器支持在文件树中新增文件）。
3. 保存后回到主页面刷新，再按「第 2 步」安装 `ssh2`。

## 5. 使用说明

| 字段 | 说明 |
|---|---|
| 主机地址 | IP 或域名，必填 |
| 端口 | 默认 22 |
| 用户名 | 登录用户名，必填 |
| 认证方式 | 密码 / 私钥 二选一 |
| 密码 | 选「密码」时必填（勾选验证登录时） |
| 私钥文件 | 选「私钥」时必填。可填**绝对路径**，或**相对工具目录**的路径（如 `id_rsa`）；点「浏览…」可列出工具目录下的候选私钥文件 |
| 私钥口令 | 加密私钥才需要填 |
| 验证登录 | 勾选 = 额外校验凭据能否真正登录；不勾选 = 只测 TCP + SSH 握手 |
| 超时（秒） | 每个阶段的超时上限，默认 10 |

结果会显示：成功/失败徽章、结论、三个阶段的耗时，以及**服务端主机密钥指纹**（SHA256）。

### 5.1 历史记录

- **保存**：填好表单后点「保存当前」，即以当前全部字段新增一条记录（列表按保存时间倒序）。
- **一键填充**：点任意记录条目，主机/端口/用户名/认证方式/密码/私钥/口令/超时/验证登录全部回填到表单，可直接点「开始测试」。
- **编辑**：点击条目填充 → 修改表单 → 点该条的「更新」，即用当前表单覆盖这条记录（保留原 id 与时间）。
- **删除 / 清空**：单条「删除」或顶部「清空」；删除/清空前都有确认。
- **持久化**：数据由后端 Node 存到工具目录 `history.json`（`GET/POST/PUT/DELETE /api/history`），平台重启、工具重启后依然保留。

## 7. 工作原理

```
┌─────────────── 浏览器 / 平台 iframe（同源）───────────────┐
│  index.html + styles.css + front.js                        │
│      └─ fetch('/api/test')  ←───────────┐                 │
└──────────────────────────────────────────┼─────────────────┘
                                           │
┌─────────────── 工具后端 app.js（Node） ───┼────────────────┐
│  ToolServer（静态服务 + 路由）            │                 │
│      ├─ 阶段1 net  TCP 连接 ─────────────┘                 │
│      ├─ 阶段2 ssh2 握手（hostVerifier 记指纹）             │
│      └─ 阶段3 ssh2 认证（ready / error 判定）              │
└───────────────────────────────────────────────────────────┘
```

关键逻辑（`app.js`）：

- **阶段 1**：用 Node 内置 `net` 模块做 TCP 连接，独立计时、超时，并映射常见错误（拒绝 / 超时 / 无法解析主机名等）为中文提示。
- **阶段 2+3**：用 `ssh2` 客户端一次完成握手与认证。`hostVerifier` 回调被调用 = 握手成功（同时用 `crypto` 计算服务端主机密钥的 SHA256 指纹）；`ready` 事件 = 认证通过；`error` 事件时：
  - 指纹已记录（握手成功）且未勾选「验证登录」→ 判定 **SSH 服务可达**（连通性通过）；
  - 指纹已记录且勾选了「验证登录」→ 判定 **认证失败**；
  - 指纹未记录 → 判定 **握手失败**，并给出原因。
- 前端把后端返回的分步结果渲染成步骤列表，每步显示耗时与成功/失败图标。

## 8. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 平台提示工具启动失败，日志里 `缺少依赖 ssh2` | 还没装 ssh2，按「第 2 步」安装后重启工具 |
| 「连接被拒绝」 | 端口未开放 / 服务未启动 / 被防火墙屏蔽 |
| 「连接超时」 | 目标不可达，或防火墙丢弃数据包 |
| 「无法解析主机名」 | 主机地址拼写错误 |
| 「SSH 握手失败」+ 目标端口不是 SSH | 端口写错，或目标没开 SSH 服务 |
| 「SSH 握手超时」 | 服务器响应慢 / 网络不稳，可调大超时 |
| 「认证失败」 | 用户名或密码/密钥不正确 |
| 「无法读取私钥」 | 私钥路径错误或权限不足；可先把私钥放进工具目录再用「浏览…」选择 |
| 「私钥解析失败」 | 文件格式不支持，或加密私钥未填正确口令 |

## 9. 安全提醒

- 测试时凭据仅走本机 `127.0.0.1` 直连工具后端，不经过任何外部服务。
- **历史记录为明文存储**：点「保存当前」会把密码/私钥口令写入工具目录 `history.json`（便于下次一键填充）。请在可信的机器上使用，并注意该目录的访问权限；不需要的记录及时「删除」。
- 不勾选「验证登录」时不会提交密码；仅当确实需要保存密码时才点「保存当前」。
- 私钥加密（设置 passphrase）后再使用是推荐做法。
