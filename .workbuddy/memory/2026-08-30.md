# 2026-08-30

## 新增「Clash 远程控制器」工具（example/clash-controller）

为工具平台新增第二个工具案例，技术栈与现有 example 保持一致（manifest + index.html + styles.css + front.js + app.js，零依赖）。

### 需求映射

- 连接配置管理：app.js 的 `/api/profiles`（GET/POST/PUT/DELETE） + `/api/profiles/activate`，数据落地到工具目录 `profiles.json`；前后端双重表单校验；保存时同步做一次连接测试给出成功/失败反馈。
- 代理组与节点控制：app.js 的 `/api/clash` 网关用 `Bearer Secret` 代理转发到 Clash 控制器（前端不直连，避免 CORS），覆盖 `version / configs / setMode / proxies / select / delay / groupDelay / reload` 八种 action。
- 刷新与测速：刷新 → `refreshData`（configs+proxies）；重载 → `PUT /configs?force=true` + 600ms 缓冲再重拉；组测速用 `GET /group/:name/delay`，内核不支持时自动回退为逐节点并发（concurrency=6）测速；全部测速在前端用并发池跑，前端节流重绘避免卡顿，可点击取消。
- 容错：friendlyError 把网络错误（ENOTFOUND/ECONNREFUSED/ETIMEDOUT/ECONNRESET/EPROTO）、HTTP 错误（400/401/403/404/408/429/504）全部翻译成可读中文；所有异步操作都有 loading 状态 + toast 反馈；接口异常不会让页面卡死（错误横幅 + 旧数据保留）。

### 关键实现细节

- 前端不直连 Clash：前端只 fetch 同源 `/api/...`，由后端用 Node 内置 http/https 携带 Bearer Secret 调控制器，路径上 `encodeURIComponent` 处理中文组/节点名，query 用 `URLSearchParams` 编码。
- IPv6 地址自动加方括号、HTTP/HTTPS 双协议支持、限流超时（连接 10s / delay testTimeout+5s / groupDelay testTimeout+15s / reload 20s）。
- 测试 URL 默认 `http://www.gstatic.com/generate_204`，超时默认 5000ms，可在「测速设置」折叠面板修改并保存到后端（设置被收敛到 [500, 30000] ms）。
- 全部测速并发 6，前端 `scheduleRender` 150ms 节流重绘避免大量节点测速时 DOM 卡顿；再次点击按钮即取消。
- 当前选中节点：行用 ::before ✓ + 蓝色高亮；切组时区分 Selector（可手动切）和 URLTest/Fallback/LoadBalance（点击行提示「自动选择，不支持手动切换」）。
- GLOBAL 组排最后；GLOBAL 内的组条目 type 显示「代理组」，可作为节点被 GLOBAL 选中（即「切换代理组」语义）。
- 测速延迟颜色：<200ms 绿、<600ms 黄、>600ms 橙、超时红、未测灰；徽章用 tabular-nums 等宽数字。
- 组测速时 body 整段置灰 (.testing) 防止误触。

### 验证情况

- 静态语法：app.js / front.js 通过 `node --check`。
- 端到端 API 测试（mock Clash 控制器在 49999）：31 项断言全 PASS，覆盖所有 CRUD、8 种 Clash action、4 类错误翻译（401 / 拒绝 / DNS 失败 / 非法参数）、设置边界、删除后状态。
- UI 渲染：用 agent-browser 实际打开 http://127.0.0.1:3910 截图，状态卡/模式切换/配置列表/代理组/节点/延迟徽章/当前选中标记/toast 全部正常显示。
- 临时测试脚本（mock + 测试脚本 + 截图）已清理，交付物只有 6 个源文件。

### 平台工具开发小贴士（后续可复用）

- 工具后端用 `process.env.TOOL_RUNTIME` 优先加载平台运行时；本地调试回退到 `src-tauri/resources/runtime/runtime.js`，再回退到内置 `MinimalToolServer`。
- 工具作者可把整目录放到用户数据目录的 `toolbox/<id>/` 下（`%APPDATA%\com.tools.platform\toolbox`），主页面刷新即可看到图标。
- 端到端 API 测试非常高效：起 mock 服务 + 工具，脚本里 30+ 断言快速回归，比靠浏览器交互更可靠。
- agent-browser 截图能很好验证 UI 整体渲染，但浏览器交互测试对状态管理敏感；复杂交互仍以 API 层断言为准。

## 平台编辑器新增「新建文件」功能

用户反馈「工具编辑器页面不能新增文件」，已补齐整条链路（原只有 list/read/write，无 create）：

- **Rust** `src-tauri/src/commands/tools.rs`：新增 `validate_new_file_path` + `create_tool_file(app, id, path, content)` 命令。校验规则：id 合法、路径相对且不含 `..`/`\`/Windows 非法字符（`?*"<>|` 等）、末段非隐藏/`_` 开头/node_modules、文件已存在则报错；**支持子目录**（如 `src/util.js`），先 `create_dir_all` 父目录再 canonicalize 校验越界（复用工具目录白名单思路）。
- **注册**：`src-tauri/src/lib.rs` invoke_handler 增加 `commands::tools::create_tool_file`。
- **前端 API**：`src/api/tauri.ts` 增加 `createToolFile(id, path, content)`。
- **编辑器 UI** `src/views/ToolEditorView.vue`：文件树头部「文件」右侧新增「＋ 新增」按钮 → 内联表单（文件名输入 + 类型下拉：空/JS/HTML/CSS/JSON/Markdown + 创建/取消），前端 `validateNewFilePath` 与后端规则一致；创建成功后刷新文件树并自动打开新文件（按扩展名走 CodeMirror 语言高亮）。快捷键：Enter 创建、Esc 收起。
- **文档**：DESIGN.md §5.3 命令表补了一行。

验证：`vue-tsc --noEmit` 通过、`vite build` 通过（chunk 警告为 CodeMirror 既有问题）、`cargo check` 通过（2m37s 增量）。未跑完整 Tauri 应用（invoke 链路由既有 list/read/write 命令模式保证）。

平台开发小贴士：编辑器相关命令注册在 lib.rs `generate_handler`；路径安全统一走 `resolve_tool_path`/`validate_new_file_path` 的 canonicalize + starts_with 校验。
